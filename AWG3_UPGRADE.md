# Переход на AmneziaWG 3.0

Ветка `awg3` создаёт новые серверы **AmneziaWG 3.0** по умолчанию.
Это изменение протокола: в конфиге появляются `HeaderProtectionKey`, `S3`, `S4`,
`ContentPaddingAddition` и диапазоны таймеров. Общий ключ защиты заголовков
генерируется криптографически и одинаков для сервера и всех его клиентов.

## Совместимость

| Сценарий | Поведение |
| --- | --- |
| Существующие серверы и клиенты AWG 1.x/2.0 | При обновлении контейнера конфиги и протокол сохраняются. |
| Новый сервер с включённой обфускацией | AWG 3.0; клиент должен поддерживать AWG 3.0. |
| Новый сервер для старых клиентов | Выберите AWG 2.0; API: `awg_version: "2"`. |
| Выключенная обфускация | Обычный WireGuard, как раньше. |
| Перевод существующего сервера на AWG 3.0 | Явная операция для остановленного сервера; все клиенты должны заново скачать и импортировать конфиги. |
| Linked Edge (AWG или VLESS) | Импорт сохраняет параметры внешнего AWG-туннеля. Версия входного AWG-сервера задаётся отдельно. |
| VLESS, пользователи, подписки, лимиты | Сохраняются; Xray остаётся версии `26.3.27`. |
| Конфиги AWG 3.1 с `RandomTrailers` / `DisableCookies` | Не поддерживаются этой сборкой AWG 3.0; импорт возвращает явную ошибку. |

**Старый клиент AWG 2.0 не может подключаться к интерфейсу AWG 3.0 с защитой
заголовков.** Сохранить такой доступ на одном интерфейсе невозможно. Можно оставить
старый сервер и создать рядом отдельный AWG 3.0 на другом UDP-порту и подсети.
Для нового порта добавьте соответствующий проброс в `docker-compose.yml`.
Не удаляйте новые поля из клиентского конфига: это не преобразует его в AWG 2.0.

Формат `web_config.json`, ID серверов и клиентов, ключи WireGuard/PSK, адреса,
порты, DNS, MTU, сроки действия, тарифы и существующие API-маршруты сохранены.
Добавлены метаданные `awg_version` и маршрут перевода. Существующие клиентские
файлы вне админки автоматически обновить невозможно.

## Обновление контейнера

Выполняйте из каталога с кодом ветки `awg3`. Не запускайте старый готовый образ
из инструкции для `main`: нужна сборка нового Dockerfile.

Сначала сделайте независимую резервную копию данных на VPS:

```sh
sudo cp -a /etc/amnezia /etc/amnezia.before-awg3-$(date +%Y%m%d-%H%M%S)
docker compose build --pull web-ui
docker compose up -d --force-recreate web-ui xray
```

Пересоздание кратковременно прерывает VPN-соединения. Оба контейнера
пересоздаются вместе, поскольку Xray использует сетевое пространство web-ui.
Монтирование `/etc/amnezia` и существующие пробросы портов остаются прежними.
Обновление образа само по себе **не переводит** существующие интерфейсы на AWG 3.

Dockerfile собирает официальные исходники, закреплённые по коммитам:

- [amneziawg-go, v3.0.20260805](https://github.com/amnezia-vpn/amneziawg-go/tree/08d68cdae27762c3e07f36bbb12d2bad32f81926)
- [amneziawg-tools, v3.0.20260730](https://github.com/amnezia-vpn/amneziawg-tools/tree/d09ecc38425082e472368dd2bf8c4c42d10cae03)
- [Описание параметров AWG 3](https://github.com/amnezia-vpn/amneziawg-go/blob/08d68cdae27762c3e07f36bbb12d2bad32f81926/README.md)

`awg-quick` запускает закреплённый `amneziawg-go`, даже если на хосте установлен
старый модуль ядра. Это сохраняет совместимость протоколов, но производительность
userspace может отличаться от модуля ядра. Нужен доступ к `/dev/net/tun`.
Для новых серверов оставьте MTU 1280, если нет проверенной причины его увеличить:
защита заголовков и padding увеличивают внешний пакет.

## Перевод существующего сервера

1. Подготовьте клиентов с поддержкой AWG 3.0 и окно переподключения.
2. Нажмите **Stop**, затем **Upgrade to AWG 3.0** и подтвердите изменение протокола.
3. Админка сохранит резервную копию в `/etc/amnezia/backups/awg3-<id>-<timestamp>/`.
   Там находятся исходный конфиг интерфейса и `web_config.json`.
4. Скачайте обновлённые конфиги существующих клиентов, переимпортируйте их и
   нажмите **Start**. Создавать клиентов заново не нужно; QR и скачивание используют
   новые параметры.

Через API: `POST /api/servers/<id>/upgrade-awg3`, с обычной авторизацией
администратора. Сервер остаётся остановленным после операции. Повторный запрос
для уже переведённого сервера не меняет ключ. Работающий интерфейс проверяется
через `ip link`, даже если сохранённый статус устарел.

При ошибке записи выполняется откат. Если процесс прерван посреди перевода,
журнал `awg3-upgrade.pending.json` позволяет восстановить старые файлы при следующем
старте до автозапуска VPN. Внешний туннель Linked Edge при переводе не изменяется.

## Откат

Для немедленного отката остановите `web-ui` и `xray`, восстановите **оба** файла
из указанного каталога резервной копии: `web_config.json` в `/etc/amnezia/`, а
`wg-<id>.conf` в `/etc/amnezia/amneziawg/`. Затем снова запустите контейнеры и
верните клиентам их старые конфиги. Образ ветки `awg3` умеет работать со старым
протоколом, поэтому менять образ для отката протокола не требуется.

Резервная копия JSON содержит состояние всей админки на момент перевода.
Её полное восстановление отменит последующие изменения других серверов и
пользователей; если такие изменения уже есть, сначала сохраните текущие данные
и восстанавливайте записи нужного сервера и его клиентов отдельно.

## Проверки

Без Docker:

```sh
python3 -m unittest discover -s tests -v
node tests/test_awg_frontend.js
node --check web-ui/static/js/app.js
```

В одноразовых контейнерах, без внешней сети и рабочих конфигов:

```sh
docker build -t amneziawg-web-ui:awg3-test .
docker run --rm --network none --privileged \
  -v "$PWD:/workspace:ro" --entrypoint python3 \
  amneziawg-web-ui:awg3-test /workspace/tests/awg_runtime_smoke.py
docker run --rm --network none --cap-add NET_ADMIN --device /dev/net/tun:/dev/net/tun \
  -v "$PWD:/workspace:ro" --entrypoint python3 \
  amneziawg-web-ui:awg3-test /workspace/tests/awg_api_smoke.py
```

Первая проверка создаёт две сетевые namespace внутри контейнера и проверяет
реальный handshake, трафик в обе стороны, MTU 1280 и `syncconf` для AWG 3.0,
AWG 2.0 и старых конфигов AWG 1.x. Вторая проверяет авторизацию, создание и
экспорт клиентов, перевод сервера, сохранение ключей и сроков, запуск/остановку
и добавление клиента на работающий AWG 3 сервер через API.
Эти проверки не заменяют проверку конкретного клиентского приложения и сети VPS.
